# Predicting Machine Failures with AI: Random Forest vs. LSTM

This project tests whether artificial intelligence can predict **how much longer a machine will keep working** before it fails, using only its sensor readings. It compares two AI models on the NASA CMAPSS jet engine dataset and was developed for the essay *Predictive Maintenance in Smart Manufacturing: Evaluating AI Models for Equipment Failure Prediction* (MSc in Artificial Intelligence, Berlin School of Business and Innovation).

!\[Experimental pipeline](figures/fig\_pipeline\_flowchart.png)

## The problem in plain words

When a machine breaks down unexpectedly, production stops and repairs are expensive. Companies usually choose between two imperfect options: fix machines after they break, or replace parts on a fixed calendar, which often throws away parts that still had plenty of life left.

**Predictive maintenance** offers a third option. Sensors on each machine measure things like temperature, pressure and vibration, and an AI model uses these readings to estimate the machine's **Remaining Useful Life (RUL)**. It is similar to a car that tells you how many kilometres are left before the brakes need attention, based on how the car has actually been driven.

## The data

The project uses the **FD001** subset of the NASA CMAPSS dataset (Saxena et al., 2008), the most widely used benchmark for RUL prediction:

* **Training set:** 100 engines recorded from a healthy state until failure.
* **Test set:** 100 different engines whose recordings stop before failure, plus a file with their true remaining life.
* **Measurements:** 3 operating settings and 21 sensors (temperatures, pressures, speeds) recorded once per operating cycle.

The data was generated by NASA with a detailed engine simulation, so the results should be confirmed on real industrial data before being used in practice. The files were downloaded from Kaggle: https://www.kaggle.com/datasets/behrad3d/nasa-cmaps.

## The two models

|Model|How it works, in simple terms|
|-|-|
|**Random Forest**|200 decision trees each make a prediction and the results are averaged, like asking a large group of experts and taking their average answer. Each tree receives a short summary of the last 30 cycles of every sensor: latest value, average, variation and trend.|
|**LSTM**|A neural network that reads the last 30 cycles one by one and keeps a short-term memory of what it has seen, similar to reading a story sentence by sentence. It works directly with the raw sensor values.|

## Results

Both models were checked with 5-fold cross-validation (split by engine, so no engine is used for both learning and testing) and then evaluated on the 100 official test engines.

|Measure|Random Forest|LSTM|Better|
|-|-|-|-|
|Cross-validation RMSE (cycles)|13.32 ± 0.72|14.80 ± 1.27|Random Forest|
|Test RMSE (cycles)|**11.71**|13.59|Random Forest|
|Test MAE (cycles)|**8.61**|10.59|Random Forest|
|NASA score (penalises late predictions)|**211**|315|Random Forest|
|Engines near failure detected (out of 25)|19|**20**|LSTM (by one engine)|
|False alarms|1|**0**|LSTM|
|Training time|**23 s**|175 s|Random Forest|
|Prediction time per engine|**1.0 ms**|9.7 ms|Random Forest|

For RMSE, MAE and the NASA score, lower is better. An alert is raised when the predicted RUL is 30 cycles or less.

### Key findings

* **The Random Forest estimated remaining life more accurately**, with lower errors in every regression measure and fewer costly late predictions.
* **The LSTM raised slightly better maintenance alerts**, but the difference was a single engine out of 25, which is too small to be conclusive.
* **Both models were often too optimistic.** Around 60% of predictions overestimated the remaining life, so a real deployment would need a safety margin, for example raising alerts earlier.
* **The Random Forest is cheaper and easier to explain.** SHAP analysis shows that its most important sensors (s3, s11 and s2) measure temperature and pressure around the high-pressure compressor, which is exactly the part that wears out in this dataset. Engineers can therefore check that the model's reasoning makes physical sense.

## How to run it

1. Clone this repository and install the libraries:

```
   pip install -r requirements.txt
   ```

2. Open the notebook in Jupyter and run all cells from top to bottom. The notebook finds the data files automatically inside the project folder.
3. Training the LSTM with cross-validation takes around 15 to 30 minutes on a laptop without a GPU. To make it faster, set `LSTM\_CV = False` in Step 0.

The results above were produced with Python 3, TensorFlow 2.21.0 and SHAP 0.52.0. Small differences in the LSTM results between runs and computers are normal.

## Limitations and next steps

* CMAPSS is simulated data from aircraft engines. The next step would be to validate the approach on real sensor data from industrial pumps, motors and conveyors, possibly using transfer learning.
* FD001 is the simplest subset (one operating condition and one type of failure). The LSTM may perform better on the more complex subsets (FD002 to FD004).
* Other models, such as Temporal Convolutional Networks (TCN), could be added to the comparison.
